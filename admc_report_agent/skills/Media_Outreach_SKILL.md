# Media Outreach

## Overview

Use this skill for repeatable media outreach work where the path is predictable:
1. understand the source material
2. identify the strongest angle
3. test regional fit
4. draft the outreach copy
5. run a final risk and style pass

This skill is for outreach and short editorial positioning. It is not for long bylines, full press releases, social calendars, or pure translation without adaptation.

## Workflow decision tree

Start by classifying the request.

- **Pitch drafting**: The user wants a new media pitch from an announcement, report, event, comment, or interview opportunity.
- **Pitch refinement**: The user already has a draft and wants it tightened, localized, shortened, or made more media friendly.
- **Regional adaptation**: The source material is global and needs a UAE, KSA, or GCC angle before drafting.
- **Quality control**: The draft is nearly done and needs a final check for hype, weak claims, unsupported facts, and readability.

If the user asks for a long contributed article, move to a thought leadership workflow instead of this skill.
If the user asks for direct Arabic localization only, stay in this skill only when the text is still an outreach asset such as a pitch, note to editor, or short interview proposal.

## Required inputs

Try to gather or infer these before drafting:

- source asset or source summary
- spokesperson name and title, if relevant
- pitch type
- target market: UAE, KSA, GCC, or wider MENA
- outlet type: business, tech, trade, mainstream, or arabic media
- strongest supporting facts, numbers, or examples
- timing hook, if one exists

If key inputs are missing, make the safest grounded assumptions and clearly label them.
Do not invent market proof points, policies, customer examples, or statistics.

## Core workflow

### Step 1: assess source readiness

Read the source material and classify it:
- announcement
- report or study
- reactive comment
- interview opportunity
- event participation
- spokesperson viewpoint

Then decide whether it is outreach ready.

A source is outreach ready when it has all of the following:
- one clear news or relevance hook
- one specific audience fit
- at least one supporting fact, example, or timely reason

If it lacks one of these, say so and either:
- ask for the missing input when necessary, or
- draft a cautious version that flags the weakness

### Step 2: choose the angle

Select one primary angle before writing.
Do not draft three competing pitch narratives in one main email.

Prefer angles in this order:
1. timely market relevance
2. strong data point or new finding
3. local or sector impact
4. access to a credible spokesperson
5. event or announcement visibility

Reject angles that are mostly:
- product description
- generic brand milestones
- vague leadership claims
- global talking points with no local consequence

When useful, produce two backup hooks, but keep the main draft focused on one route.

### Step 3: test regional fit

Check whether the angle has credible UAE, KSA, or GCC relevance.

Use this test:
- does the issue affect buyers, regulators, sectors, or infrastructure in the target market?
- is there a local policy, market trend, investment theme, or operational problem that makes it matter here?
- can the local relevance be stated in one sentence without sounding forced?

If the answer is no, say that the local fit is weak.
Do not fake localization.
In that case, either keep the pitch broader or reposition it as a regional trend discussion only if the source supports that move.

### Step 4: draft the outreach asset

Keep the structure short and readable.

Default order:
1. subject line options
2. opening line with the relevance hook
3. one short paragraph with the story angle
4. one short paragraph with support, access, or context
5. a direct and modest ask

Target lengths:
- email pitch: 120 to 220 words
- follow up note: 40 to 90 words
- editor note: 60 to 140 words
- interview pitch: 100 to 180 words
- reactive comment pitch: 80 to 160 words

### Step 5: run the final control pass

Before finalizing, check for these failure points:

- **hype**: remove self congratulatory or sales heavy phrasing
- **weak lead**: the first line should signal why this matters now
- **unsupported claims**: mark or remove facts that are not grounded in the source
- **forced localization**: remove local claims that do not hold up
- **length drift**: cut any paragraph that repeats the point
- **press release tone**: rewrite into direct outreach language

When the copy is weak, explain why in one or two sentences before presenting the revised version.

## Pitch type rules

### Interview pitch

Use when access to a spokesperson is the main value.
Lead with why the conversation matters now, not with the executive bio.
Mention the spokesperson only after establishing the topic value.

### Byline pitch

Use when the real value is a contributed point of view, not a news announcement.
Lead with the argument or fresh question the article would explore.
Do not pitch a byline as if it were breaking news.

### Exclusive pitch

Use only when the user clearly signals exclusivity.
State the exclusive element precisely.
Do not imply exclusivity if the user has not committed to it.

### Follow up pitch

Assume the editor saw the first note and needs a sharper reason to care.
Do not repeat the original email with minor edits.
Add one stronger hook, new fact, or a simpler ask.

### Reactive comment pitch

Use when the value is speed plus relevance.
Anchor the draft tightly to the current event or development.
Avoid broad background paragraphs.

## Output format

Use this default structure unless the user asks for another format.

### Standard output

**Angle**
- [one sentence explaining the core route]

**Regional fit**
- [one sentence stating UAE, KSA, GCC, or weak fit]

**Subject line options**
1. [relevance led]
2. [data led or issue led]
3. [access or interview led]

**Pitch draft**
[final email body]

**Backup hooks**
- [alternate hook 1]
- [alternate hook 2]

**Risk notes**
- [only include when there is a factual, tonal, or fit issue worth flagging]

## Style rules

Apply these by default:
- keep the tone conversational but polished
- use plain language where possible
- keep paragraphs short
- prefer specifics over adjectives
- avoid rhetorical questions unless the user explicitly wants that style
- avoid buzzwords and inflated verbs
- do not write as if the editor owes coverage
- keep asks direct and low pressure

## Guardrails

Always follow these rules:
- do not invent statistics, local policy references, customer names, or journalist interests
- if a claim depends on current events or recent market activity, verify it with current sources
- if support is missing, remove the claim or label it as a possible angle rather than a fact
- never force a UAE, KSA, or GCC angle that the source cannot support
- if the draft reads like a press release, rewrite it before returning it
- keep human review in the loop for anything sensitive, factual, or reputation affecting

## Quick examples

### Example 1
Input: a global cybersecurity report with one Middle East data point and a UAE tech media target.
Output approach: choose the strongest risk or trend finding, test whether the UAE fit is real, draft a short pitch with the finding first, then offer spokesperson access.

### Example 2
Input: a draft follow up email that sounds like a press release.
Output approach: keep only the strongest reason to care, cut boilerplate, tighten the ask, and flag any unsupported lines.

### Example 3
Input: an interview opportunity around a major regional event.
Output approach: lead with the issue the event surfaces, then position the spokesperson as a useful voice on that issue.
